## Terraform is not pre installed, and the install is also the persistence trick

```
cat <<'EOF' > ~/.customize_environment
wget -O - https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(grep -oP '(?<=UBUNTU_CODENAME=).*' /etc/os-release || lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install -y terraform
EOF
bash ~/.customize_environment
terraform --version
```

**`~/.customize_environment` runs on every Cloud Shell start**, so writing the install into it survives the session restarts these labs keep producing. The `bash ~/.customize_environment` line is what runs it now rather than at next login, which is the part easy to miss.

## The lab tells you to edit line 133, which is a moving target

> *"On line 133, inside the `gce-lb-https` module, add the following lines"*

The repo is cloned from **upstream HEAD**, so that line number is whatever the module happened to look like when the manual was written. Insert against the block instead:

```python
for i, ln in enumerate(lines):
    if re.match(r'\s*module\s+"gce-lb-https"\s*{', ln):
        lines.insert(i + 1, '  managed_ssl_certificate_domains = ["example.com"]')
        lines.insert(i + 1, "  create_ssl_certificate          = true")
        break
else:
    raise SystemExit('FAILED: no module "gce-lb-https" block found')
```

Inserting immediately after the opening brace is valid HCL and lands the arguments inside the right module regardless of how the file has drifted. The `else` on the loop matters: a silent no match here would produce a plan that succeeds and a load balancer with no certificate.

Verify by printing the block rather than trusting the edit:

```
sed -n '/module "gce-lb-https"/,/^}/p' main.tf | head -20
```

## The region defaults

Three variables in `variables.tf`, whose values come off the started page. `us-west1`, `us-east1`, `us-east4` on this run.

```python
for var, val in [("group1_region", "us-west1"), ("group2_region", "us-east1"), ("group3_region", "us-east4")]:
    pat = re.compile(r'(variable\s+"%s"\s*{[^}]*?default\s*=\s*")[^"]*(")' % var, re.S)
    s, n = pat.subn(lambda m: m.group(1) + val + m.group(2), s)
    print("%s -> %s (%d replaced)" % (var, val, n))
```

**Print the replacement count.** A `0 replaced` is the failure mode that otherwise surfaces as instances in the wrong regions and a routing test that looks broken.

`network_name` in the same file defaults to **`ml-bk-ml-mig-bkt-s-lb`**, which is the load balancer name the lab tells you to click on in the console. Useful confirmation that the cloned example is the right one.

## Then init, validate, plan, apply

```
terraform init -input=false
terraform validate
terraform plan -out=tfplan -var 'project=PROJECT_ID'
terraform apply tfplan
export EXTERNAL_IP=$(terraform output -raw load-balancer-ip)
echo "https://$EXTERNAL_IP"
```

**`terraform validate` between init and plan** costs a second and catches a mangled edit before a twelve minute apply.

**The plan must end `Plan: 43 to add, 0 to change, 0 to destroy.`** A different count means an edit went somewhere unintended, and that is the moment to stop rather than after the apply.

**`terraform output -raw load-balancer-ip`** rather than the lab's `terraform output | grep load-balancer-ip | cut -d = -f2 | xargs echo -n`, which is four processes and a fragile parse to extract one value.

The single checkpoint reads the applied infrastructure, so click it once `Apply complete! Resources: 43 added` appears.

## Verifying the content based routing

Backends take a few minutes to report healthy after the apply, which the lab acknowledges twice as *"wait for a few minutes"*. So wait on a condition rather than a guess:

```
for i in $(seq 1 20); do C=$(curl -sk -o /dev/null -w '%{http_code}' -m 20 https://$EXTERNAL_IP/); echo "root HTTP $C"; [ "$C" = "200" ] && break; sleep 20; done
for p in group1 group2 group3; do echo "== /$p"; curl -sk -m 30 https://$EXTERNAL_IP/$p | grep -oE 'us-(west1|east1|east4)-[a-z]' | head -2; done
curl -sk -o /dev/null -w "asset HTTP %{http_code}\n" https://$EXTERNAL_IP/assets/gcp-logo.svg
```

**`-k` on every curl.** The certificate is generated by Terraform's TLS provider for `example.com`, which nobody in the lab owns, so it is self signed as far as any client is concerned. That is the privacy warning the lab tells you to click through in the browser, and without `-k` curl simply refuses.

`/group1` should report a `us-west1` zone, `/group2` a `us-east1` one, `/group3` a `us-east4` one. That is the URL map, and it is the one thing in the lab worth actually checking, since the checkpoint does not.

## The community helper is the worst one in these notes

Do not run it. Its useful contribution is confirming `network_name`, and that is all.

**It destroys the config before fetching a replacement, with the failure silenced:**

```
rm -rf main.tf
wget -q https://raw.githubusercontent.com/.../main.tf
```

A 404 or a moved path leaves the directory with no `main.tf`, `wget -q` prints nothing, and `terraform init` fails on an empty configuration. Same trap as the GSP520 helper with `-q` added on top.

**And what it fetches is worse than what it deletes.** It clones the module from upstream HEAD and drops in a `main.tf` pinned in a third party repo months earlier. Module variables change; a stale `main.tf` against a current module produces `Unsupported argument` errors that read as your mistake.

**It rewrites `variables.tf` from scratch** with five variables, having never read the original. Anything else the example declares becomes an undeclared variable error.

**It never installs Terraform**, opening instead with `terraform init`, on a lab whose own text says Terraform is not pre installed.

**And `echo $DEVSHELL_PROJECT_ID | terraform plan`** answers the `project` prompt through stdin rather than passing `-var`. It works only while `project` is the sole prompted variable.

It also prints `http://` for an HTTPS load balancer, and fails on a second run because `git clone` hits an existing directory.
