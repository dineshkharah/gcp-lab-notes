# GSP523, Implement Multimodal Vector Search with BigQuery: Challenge Lab

Four tasks, **four** checkpoints, fifteen minutes stated and **5 credits**. About **ten minutes**. **Entirely Cloud Shell**, despite the lab telling you to use the BigQuery SQL Editor.

Manual last updated and last tested June 2026.

## The four blanks that are actually knowledge

Most of the bracketed placeholders are mechanical substitutions of the project, the dataset `gcc_bqml_dataset`, and table names the lab supplies. Four are not:

| Placeholder | Value |
|---|---|
| `[EMBEDDINGS_FUNCTION]` | `ML.GENERATE_EMBEDDING` |
| `[VECTOR_SEARCH_FUNCTION]` | `VECTOR_SEARCH` |
| `[DEFINE_ENDPOINT]` | `ENDPOINT = 'multimodalembedding@001'` |
| `[STATEMENT_TO_SELECT_TOP_2_RESULTS]` | `top_k => 2` |

**The last one names its own answer.** `top_k` is a named argument in a table function's argument list, not a `LIMIT`, and the value is in the placeholder's text. The circulating helper uses `top_k => 3`, which is the one error in it worth catching.

## Task 1, and the role ids

```
export REGION=europe-west1
export PROJECT_ID=$(gcloud config get-value project)
gcloud services enable bigqueryconnection.googleapis.com aiplatform.googleapis.com
bq show --format=json $PROJECT_ID:gcc_bqml_dataset | jq -r '.location'
gcloud storage ls
bq mk --connection --location=$REGION --project_id=$PROJECT_ID --connection_type=CLOUD_RESOURCE vector_conn
export CONN_SA=$(bq show --connection --format=json $PROJECT_ID.$REGION.vector_conn | jq -r '.cloudResource.serviceAccountId')
echo "connection service account=[$CONN_SA]"
gcloud projects add-iam-policy-binding $PROJECT_ID --member=serviceAccount:$CONN_SA --role=roles/bigquery.dataOwner --quiet
gcloud projects add-iam-policy-binding $PROJECT_ID --member=serviceAccount:$CONN_SA --role=roles/storage.objectViewer --quiet
gcloud projects add-iam-policy-binding $PROJECT_ID --member=serviceAccount:$CONN_SA --role=roles/aiplatform.user --quiet
gcloud projects get-iam-policy $PROJECT_ID --flatten="bindings[].members" --filter="bindings.members:$CONN_SA" --format="value(bindings.role)"
```

**The lab gives display names and the api wants ids**, the same mismatch as GSP373 and GENAI129:

| Lab's name | Role id |
|---|---|
| BigQuery Data Owner | `roles/bigquery.dataOwner` |
| Storage Object Viewer | `roles/storage.objectViewer` |
| Agent Platform User | `roles/aiplatform.user` |

The connection's service account is generated by `bq mk --connection` and looks like `bqcx-PROJECT_NUMBER-xxxx@gcp-sa-bigquery-condel.iam.gserviceaccount.com`. Extract it rather than reading it off a console page.

Two things to read before continuing. The dataset's **location must match the connection region**, `europe-west1` here; a mismatch is refused at task 2 with an error that reads like a missing connection. And `gcloud storage ls` should show a bucket named exactly the project id, which is what task 2's `uris` assumes.

## Task 2, and why the SELECT matters

```
bq query --use_legacy_sql=false <<EOF
CREATE OR REPLACE EXTERNAL TABLE \`$PROJECT_ID.gcc_bqml_dataset.gcc_image_object_table\`
WITH CONNECTION \`$PROJECT_ID.$REGION.vector_conn\`
OPTIONS (
  object_metadata = 'SIMPLE',
  uris = ['gs://$PROJECT_ID/*']
);
EOF
bq query --use_legacy_sql=false "SELECT uri, content_type FROM \`$PROJECT_ID.gcc_bqml_dataset.gcc_image_object_table\` LIMIT 5"
```

**An object table over an empty or wrong bucket creates successfully and returns zero rows.** Nothing errors, and the failure would only surface as an empty embeddings table a task later. Seven images in this run, all `image/jpeg`, with names like `Men Cable knit Sweater.jpeg`.

The connection reference can be two part, `REGION.CONNECTION`, with the project inferred. The lab's template is three part and both work.

## Task 3, and the IAM failure that looks like a wrong role

**This is the part that cost time.** The model create failed:

```
The bqcx-...@gcp-sa-bigquery-condel.iam.gserviceaccount.com does not have the
permission to access or use the endpoint. Please grant the 'Agent Platform User' role
```

`roles/aiplatform.user` **was already granted and `get-iam-policy` listed it**. The role was right; it was not yet usable. Waiting and retrying fixed it with no change at all. Now a `gotchas.md` section, because proving a binding exists is not the same as proving it works.

Retry rather than diagnose, one physical line so it survives a paste:

```
for i in $(seq 1 10); do bq query --use_legacy_sql=false "CREATE OR REPLACE MODEL \`$PROJECT_ID.gcc_bqml_dataset.gcc_embedding\` REMOTE WITH CONNECTION \`$PROJECT_ID.$REGION.vector_conn\` OPTIONS (ENDPOINT = 'multimodalembedding@001')" && echo "MODEL CREATED" && break; echo "iam not usable yet ($i), waiting 30s"; sleep 30; done
```

Then the embeddings:

```
bq query --use_legacy_sql=false <<EOF
CREATE OR REPLACE TABLE \`$PROJECT_ID.gcc_bqml_dataset.gcc_retail_store_embeddings\` AS
SELECT *, REGEXP_EXTRACT(uri, r'[^/]+\$') AS product_name
FROM ML.GENERATE_EMBEDDING(
  MODEL \`$PROJECT_ID.gcc_bqml_dataset.gcc_embedding\`,
  TABLE \`$PROJECT_ID.gcc_bqml_dataset.gcc_image_object_table\`
);
EOF
bq query --use_legacy_sql=false "SELECT COUNT(*) AS total, COUNT(ml_generate_embedding_result) AS embedded FROM \`$PROJECT_ID.gcc_bqml_dataset.gcc_retail_store_embeddings\`"
```

`total` and `embedded` should match. 7 and 7 here. A lower `embedded` means some images failed to embed, which is the same propagation problem one layer up.

**Two quoting details.** `r'[^/]+\$'` escapes the `$` so an unquoted heredoc passes a literal dollar into the regex rather than trying to expand it. And **`AS rows` does not work**: `ROWS` is a reserved keyword in BigQuery and gives `Syntax error: Unexpected keyword ROWS`. Use `total` or backtick it.

## Task 4

```
bq query --use_legacy_sql=false <<EOF
CREATE OR REPLACE TABLE \`$PROJECT_ID.gcc_bqml_dataset.gcc_vector_search_table\` AS
SELECT base.uri, base.product_name, base.content_type, distance
FROM VECTOR_SEARCH(
  TABLE \`$PROJECT_ID.gcc_bqml_dataset.gcc_retail_store_embeddings\`,
  'ml_generate_embedding_result',
  (
    SELECT ml_generate_embedding_result AS embedding_col
    FROM ML.GENERATE_EMBEDDING(
      MODEL \`$PROJECT_ID.gcc_bqml_dataset.gcc_embedding\`,
      (SELECT 'Men Sweaters' AS content),
      STRUCT(TRUE AS flatten_json_output)
    )
  ),
  top_k => 2,
  distance_type => 'COSINE'
);
EOF
bq query --use_legacy_sql=false "SELECT * FROM \`$PROJECT_ID.gcc_bqml_dataset.gcc_vector_search_table\`"
```

Two rows out, ordered by cosine distance ascending, with the men's sweater image first.

The scorer message spells out both halves: *"Please run the query for the vector search and save your search results to a table named gcc_vector_search_table."* The `CREATE OR REPLACE TABLE` wrapper is the second half; running the `VECTOR_SEARCH` alone would not score.

## Failures cascade, so fix upward

When the model create failed, three errors followed that had nothing to do with their own commands: the embeddings query reported `Not found: Model`, and both task 4 queries reported `Not found: Table ... in location europe-west1`. All three were correct as written.

Worth knowing because a screen of four errors invites four investigations when there is one cause at the top.

## The community helper

Honest about being a shortcut, and it corroborates all four fills. Four problems:

- **`top_k => 3`** where the lab says top 2, and the lab names the answer in the placeholder.
- **`REGION` from `commonInstanceMetadata.items[google-compute-default-region]`**, the fourth helper in these notes to do that. An empty region yields a connection reference like `.vector_conn` and fails two tasks later.
- **No `bigqueryconnection.googleapis.com` enable**, only `aiplatform`.
- **Blind `sleep 20` for propagation and no verification anywhere.** No role check, no row counts, no final select. Its `sleep` happens to be roughly the right idea; a bounded retry is the reliable form.

Its two part `WITH CONNECTION \`REGION.vector_conn\`` is fine, and its `REGEXP_EXTRACT(uri, r'[^/]+$')` inside a double quoted bash string is also fine, since `$'` is not a valid expansion.
